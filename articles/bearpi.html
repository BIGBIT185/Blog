嵌入式开发 / 硬件实践笔记

从一颗按钮开始，做一只自己的游戏手柄

在 BearPi 上打通硬件驱动、JS API 与 2048 界面，让代码有了触感。

刘成魁 · 根据个人简历中的项目经历整理；实践时间为 2024 年 6 月。

一个看得见、摸得着的小系统

在 BearPi-HM Micro 开发板上，我设计并实现了一只用于控制 2048 小游戏的手柄。硬件由六个按钮和七个 LED 灯组成，按钮负责输入，灯光提供视觉反馈。

这项实践的重点，是把硬件信号、系统接口与游戏界面连接起来：按下按钮之后，软件需要读到状态，游戏需要作出响应，反馈还要回到用户面前。

驱动、接口与界面，各自负责什么？

底层使用 HarmonyOS 的 HDF 框架编写手柄驱动，处理按钮输入和 LED 控制。驱动负责对接硬件，将具体的设备操作组织成可调用的能力。

中间层通过扩展 JS API 定义游戏服务接口，让前端能够读取按钮状态并控制 LED。接口在界面与驱动之间建立边界，减少上层对硬件细节的直接依赖。

前端使用 HML、CSS 与 JavaScript 实现 2048 游戏界面，处理游戏展示和操作反馈。硬件输入通过接口影响游戏状态，再反映到界面上。

按钮 / LED↔HDF 驱动↔JS API↔2048 界面

沿着一次按键追踪整个链路

把按键视为一条完整链路，有助于理解系统中每个部分的职责。出现问题时，可以分别检查硬件状态是否被读取、接口是否正确传递信息，以及界面是否更新，逐层缩小排查范围。

这种分层思路同样适用于其他嵌入式项目：先明确输入和输出，再检查每一层如何传递与处理状态。

让软件走出屏幕

这个项目加深了我对嵌入式系统、驱动编写与前后端集成的理解。一个小小的游戏手柄，可以让原本分散的知识在同一次操作里协同工作。

我也做过 STM32 光立方和基于树莓派的空调遥控装置。亲手搭建这些小系统，是我理解软件如何影响真实世界的一种方式。
